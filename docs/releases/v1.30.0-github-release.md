# v1.30.0

Rilis ini berfokus pada pemisahan mekanisme saldo awal dari receiving reguler, sehingga initial seeding stok dapat dilakukan melalui workflow admin yang eksplisit, tervalidasi, dan tetap masuk ke ledger transaksi untuk kebutuhan laporan tahunan.

## Added

- Stock Admin now has a dedicated opening-balance CSV import workflow for one-time initial stock seeding.
- Opening-balance imports now include a preview and confirmation step so admins can inspect parsed data before stock is posted.
- New `OpeningBalanceImport` and `OpeningBalanceImportItem` records keep posted opening-balance documents auditable after import.
- Opening-balance stock postings now create `Transaction(IN, reference_type=INITIAL_IMPORT)` rows with no receiving document link.
- CSV guidance and template documentation were added for the opening-balance import format.

## Changed

- Yearly stock recap now uses January 1 opening-balance rows as the selected year's initial stock.
- Opening-balance rows posted after January 1 are treated as inbound movement inside that report year.
- Future years continue from the prior year's calculated final stock rather than requiring annual re-import of opening balances.
- Direct Stock admin add, edit, and delete actions are disabled so stock remains controlled by ledger-producing workflows.
- The opening-balance import UI now follows the existing admin import flow style with format guidance, file upload, preview, and confirm-import action.

## Fixed

- The opening-balance import action is now reachable from the Stock admin screen instead of requiring the manual `/admin/stock/stock/opening-balance/import-csv/` URL.
- Opening-balance validation now rejects future effective dates, malformed rows, unknown master-data references, duplicate/conflicting batch-price rows, invalid quantities, invalid integer precision, and unsupported `receiving_type` or `supplier_code` values.
- Items marked as non-expiring can be imported without `expiry_date`, while expiring catalog items still require a valid expiry date.
- Posted opening-balance rows remain traceable through the stored import document and generated stock transactions for audit and manual correction review.

## Security

- Opening-balance import remains an admin-only stock administration workflow and is not exposed through regular receiving imports.
- Direct stock mutation through Django Admin is blocked to reduce the risk of bypassing workflow validation and ledger auditability.

## Platform Notes

- This release requires database migrations for the new opening-balance import tables.
- Existing receiving CSV imports are unchanged.
- For opening-balance CSV files, leave `receiving_type` and `supplier_code` empty because initial seeding does not use supplier or receiving-type semantics.
- Documentation and agent guidance were refreshed for the opening-balance workflow and related stock/report behavior.
